## Cursor Cloud specific instructions

LiveFrameworks is a single **Next.js 16 (Turbopack)** app. It is client-side only: state
lives in per-browser `localStorage` (`lf:*` keys), there is no database, and **no
server-side environment variables are required** to run it. Standard commands are in
`package.json` and `README.md` (`npm run dev` on port 3000, `npm test`, `npm run build`).

Non-obvious notes for developing here:

- The AI features (drawing the Business Model Canvas, running frameworks, chat) require an
  **Anthropic API key that the user supplies in the UI** (first-run form or `/settings`).
  The key is stored in `localStorage` and sent per-request to the API routes — it is never
  read from a server env var. Without a key, "Draw the canvas" / research stays disabled by
  design, so a no-key session cannot exercise the live agents.
- To exercise the app **without** a key, load a built-in demo pack via a query param on the
  home route: `/?demo=driftline`, `/?demo=ironwood`, or `/?demo=quartermast`. This fills the
  intake buckets in `localStorage`; `/pipeline` then shows the loaded engagement.
- There is **no lint script and no ESLint config** (Next 16 dropped `next lint`). Static
  checking happens through TypeScript during `npm run build`; there is no separate `npm run
  lint`.
- The `nextjs-agent-rules` block at the top of this file is regenerated by `next dev`. It is
  already committed, so the tree stays clean; do not try to delete it in a diff.
