## Theory of Constraints

The system-wide constraint is the unbuffered phone/dispatch layer — one generalist and two overloaded CSRs with no after-hours coverage — which throttles volume into both repair and install revenue before any other resource even gets a chance to work. Fixing this drum is fast and cheap relative to marketing spend or hiring, so TOC logic says exploit and subordinate to it now, elevate install-quoting and crew capacity next, and treat ad spend as rope that should not be released until the drum is stabilized.

### The Constraint

- Inbound call answering and dispatch — concentrated in Carla Nunez plus two CSRs with no after-hours/weekend coverage — is THE constraint: it gates volume into repair and install simultaneously and is already causing lost and near-lost deals.

### 1. Identify

- Multiple independent first-party sources (owner, office manager, org chart, call transcripts) converge on the same bottleneck: calls go unanswered during peak and after-hours because one person owns five functions with no backup, and this already produced a near-lost repair job and a lost install deal — the classic TOC signature of demand exceeding a single resource's delivery capacity.

### 2. Exploit

- Route overflow calls to whichever CSR/tech is free first rather than defaulting to voicemail, and stop pulling Jesse into permit paperwork during peak call hours.

- Give every CSR a standing script step to mention the $25 referral credit and to proactively text customers before an appointment window slips, squeezing more value out of calls already being answered at zero incremental headcount cost.

- Have Marcus (senior tech) continue covering Nate's install quotes when Nate is on a job, as already happens informally, to prevent quote requests from stalling entirely during peak install-crew activity.

### 3. Subordinate

- Do not increase marketing/ad spend to generate more inbound calls until the phone/dispatch drum can absorb current volume — more demand into an already-overflowing intake only produces more voicemails and lost quotes, not more revenue.

- Hold off on adding a second install crew until quote turnaround is fixed and quote-to-close volume actually justifies more install capacity — expanding downstream capacity ahead of the constraint just builds costly idle capacity.

- Keep the founder's (Walt's) informal, untold schedule changes from bypassing Carla's queue, since undocumented interventions upstream of the constraint disrupt the buffer meant to protect it.

### 4. Elevate

- Deploy after-hours/overflow call coverage (answering service or AI receptionist) and add a cross-trained second CSR/scheduler so Carla is no longer a single point of failure — this is the direct capacity increase on the constraint itself.

- Once the phone drum is stabilized, elevate the secondary downstream constraint by adding a dedicated install estimator decoupled from crew supervision, so Nate's dual role stops throttling install quote speed.

- Only after both are relieved, evaluate a second install crew — but sequence this last given 45-90+ day skilled-trade hiring lead times, which make it the slowest and most expensive elevate option.

### 5. Repeat

- Once live-answer rate and quote turnaround are measurably fixed, re-run constraint identification — the next binding constraint is most likely install crew capacity (a hard physical ceiling) or technician headcount, given the tight skilled-trades labor market.

- Re-evaluate whether marketing spend is now a safe investment only after the drum (dispatch) and the first elevate step (estimator) are confirmed to be absorbing current volume without leakage.
